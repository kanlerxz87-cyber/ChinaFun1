Travel-time model (estimate — not a measured trip)

Distance between the hotel and the restaurant is the great-circle distance computed from coordinates (restaurant coordinates: OpenStreetMap via Nominatim; hotel coordinates: same method, checked against the hotel's published address).

estimated_minutes = walk_wait_min + distance_km × detour_factor × min_per_km
walk_wait_min  = 16   (walk to station + platform wait + walk from station)
detour_factor  = 1.3   (street/metro routing vs. straight line)
min_per_km     = 2.5   (≈24 km/h effective incl. dwell time)

Why it is an estimate: no public journey-planner output was available in this environment, so the model deliberately errs conservative. It is not a substitute for a live transit check — every hotel row must be re-checked in a journey planner before booking (this is on the Flagged for Review page).

Coordinates: restaurant coordinates are street-level OpenStreetMap geocodes (house numbers are not resolved in Shanghai, so expect ±1 km) except Taian Table, which uses the coordinate MICHELIN publishes on its own page. Hotel coordinates are OpenStreetMap building/polygon centroids. Because of that error margin, treat any two hotels whose counts differ by 1–2 restaurants as tied. No live journey-planner output was obtainable in this environment (Google/Apple/Baidu transit and Overpass were unreachable), so the 60-minute test is a banding device, not a measured trip.

How to read this site: a value is only shown when an official/primary source was read on the date shown. Empty cells are intentionally empty and appear on the Flagged for Review page. Travel times are labelled estimates from a documented model (method).
