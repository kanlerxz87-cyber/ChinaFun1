Hotels ranked by MICHELIN cluster access

This is the ranking you asked for: which hotel puts the most starred restaurants inside a one-hour transit budget. The method is published in full below, and the code that produced these numbers is in the repository, so you can check or re-run it.

Honesty first: these minutes are modelled, not routed. No live transit-routing engine was reachable from this environment. The figures come from straight-line distance between independently verified coordinates, converted to a transit time using declared assumptions. Treat every minute as ±10 minutes. A real journey planner will give you the true figure. What this model does do reliably is rank the hotels relative to each other, because the same assumptions are applied to all of them.

Note the model has a floor: because it always assumes a 6-minute walk to a station, a restaurant 0.32 km away still scores 7 minutes. Real walking time would be shorter. This is why the ranking is only meaningful between hotels, not as an absolute travel time.

The method, in full

  1. Coordinates. Restaurants: taken from the map link embedded on each MICHELIN Guide restaurant page. Hotels: taken from OpenStreetMap via the Photon geocoder. Restaurants whose coordinates could not be verified were excluded, not estimated.
  2. Distance. Great-circle (haversine) distance between the two points, on a 6,371.0088 km sphere.
  3. Transit conversion. The assumed model is:
    • 6-minute walk from hotel door to metro entrance;
    • rail distance = straight-line distance × 1.25 detour factor;
    • average speed 30 km/h including stops;
    • +6 minutes if straight-line distance exceeds 4 km (assumed line change).
  4. Ranking rule. Primary key: total stars reachable within 60 minutes. Secondary: count of starred restaurants within 60 minutes. Tie-break: lower mean modelled time across all five restaurants.

Two hotels deliberately left out of the ranking
